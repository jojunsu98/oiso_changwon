## 3. 개발 인계 핵심

### 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

### 핵심 구조

- `app.py`: Streamlit 화면/배포 진입점
- `src/agent.py`: Agent 질문 이해 → 도구 선택·호출 → 답변 검증 → 규칙 기반 fallback
- `src/policy_matcher.py`: 정책 24건 4단계 판정·일정 이벤트
- `src/policy_engine.py`: 기업노동자 전입지원금 등 규칙 판정
- `src/settlement_engine.py`: 전입일 기준 정착 일정
- `src/mission_manager.py`: 1~6개월 정착 미션
- `src/progress_manager.py`: 진행률/현재 단계
- `src/state_manager.py`: SQLite 체크·메모 저장
- `src/schedule_export.py`: .ics 및 정착 리포트
- `src/email_alerts.py`: 동의 기반 이메일 알림
- `src/activity_manager.py`: 생활 정보 60곳
- `src/naver_map_links.py`: 네이버 지도 검색 링크
- `src/policy_resource_manager.py`: 공식 링크 검증

### Agent 도구 5개

1. `get_my_situation`
2. `search_policies`
3. `search_activities`
4. `lookup_dialect`
5. `find_complaint_channel`

### Agent 동작 원칙

- GPT-4.1 mini가 질문 의도와 필요한 도구를 선택
- 정책 자격 판정 자체는 LLM이 아니라 **규칙 기반 Python 로직**
- 연락처·링크는 검증 데이터와 대조
- 잘못된 값이 감지되면 재작성, 실패 시 규칙 기반 답변으로 fallback
- 긴급/위기 문장은 AI를 거치지 않고 112·119·109 등으로 즉시 안내
- 최대 도구 호출 라운드 제한을 둠
- 실제 최종 자격 판단은 담당 기관 확인을 전제로 함

### 저장/개인정보

- 회원가입 없음
- 닉네임·조건 기준으로 체크/메모 저장
- 이메일은 사용자가 신청하고 동의한 경우에만 저장
- API 키·메일 계정 비밀번호는 Streamlit Secrets에서 관리
- 저장소에 키/비밀번호를 넣지 않음

### 배포/수정 시 주의

- `app.py`, `requirements.txt`, `.streamlit/`, `src/`, `data/` 위치를 임의로 변경하지 않기
- 기능이 정상 동작하면 제출 직전 대규모 refactor 금지
- 테스트를 통과시키기 위해 assertion/timeout을 임의로 약화하지 않기
- 수정 후 최소 compile → focused test → full regression → Streamlit 기동 확인 순서 권장

- ‘오이소창원에게 물어보기’

용도:

사람/코드가 한 일:
- 도구 5개 설계
- 정책 판정 규칙 설계

- 연락처·링크 후검증
- fallback 설계
- 최종 UI/문구 검수

- Complaint / Dialect form의 label/input/button이 container 경계에 몰려 보이거나 내부 여백이 불균형한 문제.
- Ask 입력창에서 outer frame + 내부 연한 background + send button이 겹쳐 다중 layer처럼 보이는 문제.
- Explore/생활정보 페이지의 Hero → heading → filter → cards, 카드 row 간 spacing 부족.
- `자세히 보기` / `지도에서 보기` CTA의 카드별 위치와 간격 통일 필요.
- `이용 참고사항 자세히 보기`는 P2 우선순위로 line-height / bullet 간격 개선 여지 있음.

### E. 사용자 노출 한글 문구 오염 — P0

실제 화면에서 정상 기능명과 전혀 다른 한글 문구가 노출되는 현상이 발견되어 최우선 감사 대상으로 지정했습니다.

예:
- 정착/정책/행정 등 정상 용어가 다른 의미의 단어로 변질
- 행정 안내가 도박 등 서비스와 무관한 표현으로 보이는 사례
- 실제 로그인 기능과 맞지 않는 `로그인하세요` 류 CTA
- 공식 기능명이 임의 문구로 교체된 사례

최종 원칙:
- 문구를 새로 창작하지 않고 README / origin/main 정상 문구 / 제출 문서 / 검증 데이터의 공식 명칭을 Source of Truth로 복원.
- 맞춤법만이 아니라 **서비스 의미가 실제 기능과 일치하는지** 전수 검사.
- 사용자 노출 문자열 수정 목록을 최종 보고에 남김.
