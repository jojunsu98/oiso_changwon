## 1. 서비스 개요

- **서비스명:** 오이소창원 Lite
- **배포 URL:** https://oiso-changwon-lite.vercel.app
- **한 줄 설명:** 창원 전입 청년의 첫 180일 동안 놓치기 쉬운 혜택과 할 일을 내 조건으로 판정하고, 일정과 다음 행동으로 정리하는 AI 정착 코디네이터
- **슬로건:** 창원에서 너의 내일을 응원해!
- **목적:** 창원으로 새로 전입했거나 전입을 준비하는 청년이 흩어진 정책·생활 정보를 직접 찾아 비교해야 하는 부담을 줄인다.
- **핵심 흐름:** 내 조건 → 판정 → 일정 → 안내
- **정보 원칙:** 정책 자격은 규칙으로 비교하고, AI는 검증 자료 범위에서 결과를 설명한다. 최종 자격은 담당 기관 확인이 필요하다.

## 2. 문제 정의

창원 전입 청년은 주거·취업·교통·복지·생활 정보를 여러 기관과 웹페이지에서 각각 찾아야 한다. 정책 이름을 알아도 본인의 전입일·재직 상태·연령과 맞는지 판단하기 어렵고, 신청 가능 시점과 다음 행동을 놓치기 쉽다.

서비스는 다음 세 가지 문제를 해결한다.

1. 흩어진 정보를 한 화면에서 확인한다.
2. 사용자 조건과 정책 요건을 규칙으로 비교한다.
3. AI가 검증 자료 범위 안에서 우선순위와 다음 행동을 설명한다.

## 3. 타겟 사용자

### 주요 사용자

- 창원으로 최근 전입한 만 19~39세 청년
- 창원 전입을 준비하며 정책과 생활 정보를 미리 확인하려는 청년
- 주거·취업·교통·생활 불편·지역말 정보를 한곳에서 확인하려는 사용자

### 대표 사용자 시나리오

1. 사용자가 나이·전입일·직업·재직 여부·전입 전 거주 기간·차량 여부를 입력한다.
2. Python 백엔드가 정책 24건을 규칙 엔진으로 판정한다.
3. 결과를 네 단계로 구분한다.
4. AI가 우선 확인할 정책과 다음 행동을 설명한다.
5. 사용자가 자연어 질문을 입력하면 관련 정책·민원·지역말·생활 활동 자료를 검색해 답한다.

## 4. 기존 오이소창원과의 관계

오이소창원 Lite는 새로운 콘셉트가 아니다. 기존 팀 프로젝트의 목적·타겟·브랜드·검증 데이터·정보 원칙을 유지하면서 개인 미션의 기술 요건에 맞춰 웹 구조를 다시 구현했다.

| 구분 | 기존 오이소창원 | 오이소창원 Lite |
|---|---|---|
| 서비스 목적 | 창원 전입 청년 정착 지원 | 동일 |
| 핵심 기능 축 | 혜택·일정·민원·지역말·Agent | 동일 |
| 프론트엔드 | Streamlit | HTML/CSS/JavaScript |
| 백엔드 | Streamlit 내부 Python | Vercel Python Functions |
| 배포 | Streamlit Cloud | Vercel |
| AI 제공자 | 기존 Agent 설정 | Gemini 우선, OpenAI 대체 |

운영 복잡도가 높은 이메일 알림·영구 저장·전체 리포트·캘린더 파일은 Lite 범위에서 제외했다.

## 6. AI 기능 설계

### 기능 A. 맞춤 정착 브리핑

**입력**

- 만 나이
- 창원 전입일
- 현재 하는 일
- 창원 사업장 재직 여부
- 전입 전 타지역 거주 기간
- 차량 보유 여부

**처리**

1. JavaScript가 입력값을 검증하고 JSON으로 구성한다.
2. `fetch('/api/recommend')`로 POST 요청한다.
3. 기존 규칙 엔진이 정책 24건을 판정한다.
4. AI 제공자가 상위 판정 결과를 4~6문장으로 요약한다.
5. 브라우저가 단계별 수·정책 카드·AI 요약을 표시한다.

**출력**

- 4단계별 정책 개수
- 정책명·판정·이유·지원 내용
- 신청·확인 방법과 일정
- AI 정착 브리핑

### 기능 B. AI 코디네이터

**입력**

최대 500자의 자연어 질문

**처리**

1. `fetch('/api/chat')`으로 질문을 전달한다.
2. Python이 검증 JSON에서 관련 자료를 검색한다.
3. Gemini API를 우선 호출하고, 실패 시 OpenAI API를 대체 호출한다.
4. 자료에 없는 사실은 만들지 않는다.
5. 참고 자료명과 공식 확인 경로를 함께 표시한다.

**출력**

- 질문에 대한 한국어 답변
- 확인 조건과 다음 행동
- 참고 자료·공식 링크

## 10. 보안·개인정보

- API 키는 Vercel Secret 환경 변수에서 관리한다.
- 브라우저·코드·README·캡처에 키를 노출하지 않는다.
- 실명·연락처·주민등록번호를 입력받지 않는다.
- 질문 길이와 요청 크기를 제한한다.
- 서버 내부 오류와 사용자 메시지를 분리한다.
- 키 노출이 의심되면 키를 폐기·재발급한다.

## 13. 실제 오류 개선 이력

| 오류 | 확인된 원인 | 적용한 개선 | 최종 결과 |
|---|---|---|---|
| Vercel 404·빈 화면 | Application Preset이 Python으로 설정되고 `main` 브랜치가 운영 주소를 덮어씀 | Framework를 `Other`로 변경하고 `codyssey-vercel-lite`를 Production으로 재배포 | 운영 URL 정상 표시 |
| 키 미설정 메시지 | 코드의 변수명과 등록 이름이 다르고 일부 키가 Development에만 적용됨 | 변수명 호환 처리와 Production·Preview·Development 적용 확인 | 배포 함수가 키를 읽음 |
| Gemini `Invalid header value` | 여러 환경 변수 문장이 `GEMINI_API_KEY` 한 값에 함께 입력됨 | `.env` 블록이어도 해당 키 한 줄만 추출하는 비밀값 정규화 로직 추가 | Gemini 호출 정상화 |
| OpenAI `RateLimitError` | API 사용 한도 또는 결제 크레딧 제한 | Gemini 우선 호출, OpenAI 대체 호출 구조 적용 | OpenAI 쿼터와 무관하게 AI 응답 생성 |
| 오류 메시지가 모호함 | 모든 API 예외를 같은 메시지로 처리 | 인증·권한·쿼터·모델·연결·시간초과를 구분하고 서버 로그와 사용자 안내 분리 | 원인 확인 시간 단축 |
| 진단 중 비밀값 노출 가능성 | 임시 상세 오류 응답에 환경 변수 일부가 포함될 수 있음 | 상세 진단 제거, 비밀값 패턴 검사, 키 폐기·재발급 원칙 문서화 | 최종 응답 노출 0건 |

### 오류 개선에서 배운 점

- 로컬 코드가 맞아도 배포 프리셋·브랜치·환경 변수 범위가 다르면 서비스는 작동하지 않는다.
- 환경 변수는 이름뿐 아니라 값의 형식과 적용 환경을 함께 검증해야 한다.
- 외부 AI API는 인증 성공과 실제 호출 가능 상태가 다를 수 있으므로 쿼터·결제·모델 권한을 별도로 확인해야 한다.
- 사용자에게는 비밀값 없는 안전한 메시지를 제공하고, 상세 원인은 서버 로그에서 확인해야 한다.
