# 오이소창원 Lite 오류 개선 보고서

검증일: 2026-10-15  
배포 URL: https://oiso-changwon-lite.vercel.app

## 1. 개선 목표

기존 Streamlit 팀 프로젝트를 코디세이 개인 미션 규격인 순수 HTML/CSS/JavaScript + Vercel Python Functions 구조로 재구현하고, 실제 배포 환경에서 발생한 오류를 원인별로 분리해 해결했다.

## 2. 주요 오류와 해결 과정

### 오류 1. 기존 서비스가 과제 기술 구조와 불일치

- **현상:** Streamlit 앱은 작동했지만 순수 HTML/CSS/JavaScript, `fetch('/api/...')`, Vercel Python Functions 요구를 충족하지 못했다.
- **원인:** 기존 앱은 UI와 백엔드를 Streamlit이 함께 처리했다.
- **개선:** 동일 콘셉트·브랜드·검증 데이터를 유지하면서 Lite 버전을 별도 브랜치에서 재구현했다.
- **결과:** 프론트엔드와 `api/` Python 백엔드가 분리되었다.

### 오류 2. 첫 Vercel 배포에서 화면 미표시 및 404

- **현상:** Production URL에 빈 화면 또는 `404 NOT_FOUND`가 나타났다.
- **원인:** Application Preset이 Python으로 잡혔고, 과제 브랜치가 아닌 `main` 브랜치 배포가 운영 주소를 덮어썼다.
- **개선:** 프리셋을 `Other`로 변경하고 `codyssey-vercel-lite` 배포를 Production으로 지정했다.
- **결과:** 고정 URL에서 HTML 화면과 API 엔드포인트가 정상 응답했다.

### 오류 3. 환경 변수를 등록했지만 AI 키 미설정으로 인식

- **현상:** 화면에 `OPENAI_API_KEY를 설정해야 합니다`가 표시됐다.
- **원인:** 키 이름이 코드가 찾는 이름과 달랐고, 일부 키는 Development에만 적용됐다.
- **개선:** 변수명 호환 로직을 추가하고 Production·Preview·Development 범위를 확인했다.
- **결과:** 배포 함수가 환경 변수를 읽고 외부 AI 호출 단계까지 진행했다.

### 오류 4. Gemini 요청에서 Invalid header value

- **현상:** Gemini 호출이 요청 전 단계에서 실패했다.
- **원인:** `GEMINI_API_KEY` 값에 줄바꿈과 다른 환경 변수 문장이 함께 붙여넣어졌다.
- **개선:** 환경 변수 값이 `.env` 블록 형태로 잘못 입력되어도 해당 키 한 줄만 추출하는 정규화 함수를 추가했다.
- **결과:** Gemini API 호출이 정상화됐다.

### 오류 5. OpenAI RateLimitError

- **현상:** OpenAI 키는 인증됐지만 AI 응답이 502로 실패했다.
- **원인:** API 사용 한도 또는 결제 크레딧 제한이었다.
- **개선:** Gemini를 기본 제공자로 사용하고, Gemini 실패 시 OpenAI를 대체 호출하도록 구성했다.
- **결과:** OpenAI 쿼터에 의존하지 않고 AI 응답이 정상 생성됐다.

### 오류 6. 사용자 오류 메시지가 지나치게 일반적

- **현상:** `AI 응답을 불러오지 못했습니다`만 보여 원인 구분이 어려웠다.
- **원인:** 예외 유형을 모두 같은 메시지로 처리했다.
- **개선:** 인증·권한·쿼터·모델·연결·시간초과 오류를 구분하고 서버 로그와 사용자 메시지를 분리했다.
- **결과:** 디버깅 속도가 빨라졌고 사용자에게 비밀값 없이 필요한 안내를 제공한다.

### 오류 7. 진단 과정의 보안 위험

- **현상:** 원인 파악을 위해 임시 상세 진단을 추가했을 때 비밀값이 응답에 포함될 가능성이 확인됐다.
- **개선:** 상세 진단 출력을 즉시 제거하고, 응답 내 키 패턴 검사와 키 재발급 원칙을 적용했다.
- **결과:** 최종 API 응답 검사에서 비밀값 노출 0건을 확인했다.

## 3. 최종 안정화 구조

```text
Gemini API 정상
  → Gemini 응답 사용

Gemini API 실패
  → OpenAI API 대체 호출

두 제공자 모두 실패
  → HTTP 502와 안전한 사용자 안내

검증 자료 없음
  → 추측하지 않고 질문 구체화 안내
```

## 4. 개선 전후 비교

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 배포 | Streamlit 또는 잘못된 Vercel 브랜치 | Vercel Production 고정 URL |
| 프론트·백엔드 | Streamlit 결합 | HTML/CSS/JS + Python Functions 분리 |
| AI 제공자 | 단일 제공자 의존 | Gemini 우선 + OpenAI 대체 |
| 키 처리 | 이름·범위·줄바꿈 오류 취약 | 변수명 호환·정규화·Secret 관리 |
| 오류 메시지 | 일반 메시지 | 오류 유형별 안내 |
| 보안 검증 | 수동 확인 | 키 패턴 자동 검사·진단 제거 |
| 테스트 | 화면 중심 | API·입력 검증·긴급 경로·반복 호출 |

## 5. 남은 개선점

1. 환경 변수는 처음부터 한 줄씩 입력하도록 운영 가이드를 더 명확히 한다.
2. 정책 데이터 정기 갱신 일정을 설정한다.
3. 외부 AI 장애 시 규칙 기반 요약만으로도 충분한 안내를 제공하도록 강화한다.
4. 민원·지역말 검색의 키워드 동의어를 확장한다.
5. 실제 사용자 3~5명을 대상으로 모바일 사용성 테스트를 진행한다.
6. 기존 키 노출 의심 시 Gemini·Kakao 키를 폐기하고 새 키로 교체한다.
